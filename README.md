# Trend Entries — เทรนด์ใหญ่และจังหวะเข้า

อินดิเคเตอร์ Pine Script v6 สำหรับสินทรัพย์และกรอบเวลาที่ผู้ใช้เลือก แยกเทรนด์ใหญ่ กรอบยืนยัน และจังหวะ BUY/SELL หลังย่อตัว พร้อมแผนอ้างอิง Entry/SL/TP บนกราฟ **15 นาที** ค่าเริ่มต้นใช้ **4 ชั่วโมงเป็นเทรนด์ใหญ่ และ 1 ชั่วโมงยืนยัน** กฎใช้ EMA, ADX, ATR และ tick ของสัญลักษณ์บนกราฟ ค่าเริ่มต้นไม่ได้ปรับให้เหมาะกับทุกตลาด และยังไม่ได้ทดสอบผลตอบแทนกับข้อมูลตลาดจริง

## ติดตั้งหรืออัปเดต

1. เปิดสัญลักษณ์และกรอบเวลาที่ต้องการบน **กราฟมาตรฐานที่แบ่งแท่งตามเวลา** เช่น หุ้น, Forex, ทอง, คริปโต หรือ futures
2. เปิด **Pine Editor** แล้วสร้างอินดิเคเตอร์ใหม่ หรือเปิดสคริปต์เดิม
3. วางโค้ดทั้งหมดจาก [trend_entries.pine](./trend_entries.pine) แทนโค้ดเดิม แล้วกด **Save**
4. กด **Add to chart** หรือ **Update on chart** หากมีตัวเก่าซ้ำอยู่ให้เหลือเฉพาะเวอร์ชันที่ต้องการ
5. ตรวจ Settings อีกครั้ง และสร้าง Alert ใหม่หลังอัปเดตโค้ดหรือค่าตั้ง

ชื่อบนกราฟคือ **TrendEntry** ชื่อเต็ม **Trend Entries | Main Trend + Confirmation** ไม่ออกสัญญาณเข้าบน Tick หรือกราฟสังเคราะห์ เช่น Heikin Ashi, Renko และ Range ไฟล์เดิม `gold_trend_15m.pine` เปลี่ยนชื่อเป็น `trend_entries.pine` แล้ว

## อ่านหน้าจอแบบย่อ

สถานะแสดงเป็นป้ายภาษาไทยใกล้แท่งล่าสุด ไม่มีตารางตรึงมุมจอ เช่น:

```text
4 ชม. ↑ เทรนด์ใหญ่ขึ้น · มอง BUY
1 ชม. ขึ้น · ทิศตรงกัน
15 นาที · ย่อ/พักตัว · รอยืนยัน
รอแท่งปิดยืนยัน BUY
```

อ่านจากบนลงล่าง: **เทรนด์ใหญ่ → กรอบยืนยัน → ภาวะกราฟเข้า → สิ่งที่กำลังรอ/แผนเดิม** คำว่า “มอง BUY/SELL” บอกฝั่งของเทรนด์ใหญ่ ยังไม่ใช่สัญญาณเข้า ชี้เมาส์ที่ป้ายเพื่อดูข้อมูลแท่งปิด, ADX, เหตุผลที่รอ, ข่าว, ต้นทุน และแผนล่าสุด หรือเปิด **Data Window** แล้วชี้แท่งย้อนหลัง ป้ายผูกกับแท่งล่าสุดและตำแหน่งราคา จึงเลื่อนตามกราฟเมื่อซูมหรือเลื่อน ไม่ได้ตามแท่งที่เมาส์ชี้

ใน **Settings → การแสดงผล** ปรับ `แสดงสถานะใกล้แท่งล่าสุด`, `แสดงชื่อกำกับเส้นราคา`, ระยะป้ายจากแท่งล่าสุด (เริ่มต้น **3 แท่ง**) และขนาด **เล็ก / ปกติ / ใหญ่** (เริ่มต้นปกติ) ค่าเริ่มต้นเปิด EMA, BUY/SELL, แผนราคา และ **สีพื้นตามเทรนด์ใหญ่ย้อนหลังแบบจาง 95%**; ปิดสีแท่ง, จุดเปลี่ยน UP/DOWN และเส้น S/R หากอัปเดตแล้วยังคงค่าการแสดงผลเดิม ให้ปรับเฉพาะสวิตช์ในหมวดนี้ตามต้องการ

ป้าย BUY/SELL ที่เกิดย้อนหลังยังอยู่ตามแท่งสัญญาณ ส่วนป้ายชื่อ **เข้า (Entry) / ตัดขาดทุน (SL) / เป้าหมาย (TP)** แสดงเฉพาะแผนที่ยังติดตามและเปิดเส้นแผนไว้ เมื่อแผนจบจะลบป้ายชื่อราคาเก่า รายละเอียดแผนที่จบแล้วอยู่ใน tooltip โดยระบุว่าไม่ใช่จุดเข้าใหม่ และใน Data Window (`Active plan side = 0` หมายถึงไม่มีแผนทำงาน)

## อ่านแนวโน้มสามกรอบเวลา

| ทิศทางในแต่ละกรอบเวลา | เงื่อนไข EMA ค่าเริ่มต้น |
| --- | --- |
| ขึ้น | EMA 20 > EMA 50, ราคาปิด > EMA 50 และ EMA 50 สูงกว่าค่าเมื่อ 3 แท่งก่อน |
| ลง | EMA 20 < EMA 50, ราคาปิด < EMA 50 และ EMA 50 ต่ำกว่าค่าเมื่อ 3 แท่งก่อน |
| ยังไม่ชัด | เงื่อนไขขึ้นหรือลงยังไม่ครบ ไม่ได้ยืนยันว่าราคาเป็น Sideway เสมอไป |

EMA และความชันนับแท่งของกรอบเวลานั้น Fast EMA ต้องสั้นกว่า Slow EMA **กราฟเข้าเพิ่มเงื่อนไข ADX ≥ 20** โดย DI length/ADX smoothing เริ่มต้น 14/14 และปิดตัวกรองได้ ส่วนเทรนด์ใหญ่และกรอบยืนยัน **ไม่ใช้ ADX** ทั้งสามกรอบต้องมีประวัติเพียงพอก่อนใช้เข้าเทรด เส้น EMA ที่วาดบนกราฟเป็นของกราฟเข้า ไม่ใช่ EMA 4 ชั่วโมง

หัวป้าย สีพื้น สีแท่งเมื่อเปิดใช้ และจุดเปลี่ยน UP/DOWN อิง **เทรนด์ใหญ่** จึงยังเขียวได้แม้กราฟ 15 นาทีพักตัวหรือสวนลง บรรทัดกราฟเข้าแยกสถานะนี้ไว้: “สวนเทรนด์ใหญ่” เมื่อทิศตรงข้าม; “ย่อ/พักตัว” เมื่อราคาปิดอยู่ผิดฝั่ง EMA เร็วของกราฟเข้าโดยยังไม่เข้าเงื่อนไขทิศตรงข้าม เป็นคำอธิบายภาวะราคา ไม่รับรองว่าการย่อจะจบ เส้น EMA เคลื่อนตามราคาสด แต่ทิศทางและสัญญาณคงผลแท่งปิดล่าสุด

ใน Data Window ค่า `Confirmed main trend` เป็นเทรนด์ใหญ่, `Confirmed confirmation trend` เป็นกรอบยืนยัน และ `Confirmed trend (1 up / 0 unclear / -1 down)` ยังเป็นกราฟเข้า ค่าทิศทางใช้ `1 / 0 / −1` เหมือนกัน

## BUY/SELL ต้องผ่านสองขั้น

ก่อนเตรียมเข้า ต้องมีทิศทาง **กราฟเข้า = กรอบยืนยัน = เทรนด์ใหญ่ และไม่เป็น Neutral** เมื่อเปิดตัวกรอง เช่น BUY ต้องเป็นขึ้นครบ 15 นาที/1 ชั่วโมง/4 ชั่วโมง ไม่ติดช่วงข่าวที่กรอก, ไม่มีแผนเดิมทำงาน และห่างจากสัญญาณก่อนอย่างน้อย 4 แท่งตามค่าเริ่มต้น การตรงกันครบยังต้องผ่านสองขั้นด้านล่าง ไม่ใช่ให้เข้าทุกครั้งที่ราคาย่อ

| ขั้นตอน | BUY | SELL |
| --- | --- | --- |
| 1. เตรียมหลังย่อกลับเข้าแถบ EMA | เทรนด์กราฟเป็นขึ้นทั้งแท่งก่อนและแท่งนี้; low ของแท่งก่อนอยู่เหนือ EMA เร็วของแท่งก่อน; ช่วง high–low แท่งนี้แตะแถบระหว่าง EMA ทั้งสอง และปิดเหนือ EMA ช้า | เทรนด์กราฟเป็นลงทั้งแท่งก่อนและแท่งนี้; high ของแท่งก่อนอยู่ใต้ EMA เร็วของแท่งก่อน; ช่วง high–low แท่งนี้แตะแถบ EMA และปิดใต้ EMA ช้า |
| 2. ยืนยันในแท่งถัดมาหรือภายหลัง | ปิดเหนือ EMA เร็ว, เหนือ high ของแท่งก่อนหน้าทันที และ close > open | ปิดใต้ EMA เร็ว, ใต้ low ของแท่งก่อนหน้าทันที และ close < open |

แท่งที่เตรียม setup จะยังไม่ส่ง BUY/SELL ต้องมีแท่งยืนยันคนละแท่งภายใน **6 แท่งหลังเตรียม** ตามค่าเริ่มต้น และผ่าน S/R, reward/risk และขนาดสถานะถ้าเปิดคำนวณจำนวน

**หากเทรนด์กราฟกลายเป็น Neutral แม้เพียงหนึ่งแท่งปิด จะยกเลิก setup ทันที** เช่น ADX ต่ำกว่าเกณฑ์หรือราคาปิดผิดฝั่ง EMA ช้า เมื่อเปิดตัวกรอง การที่เทรนด์ใหญ่/กรอบยืนยันไม่ชัดหรือไม่ตรงกันก็ยกเลิก เช่นเดียวกับการเปลี่ยนทิศทาง, ข่าว หรือหมดเวลา การพยายามยืนยันที่ไม่ผ่านตัวกรองจะใช้ setup นั้นไปแล้ว ต้องรอการย่อครั้งใหม่จากนอกแถบ EMA ไม่ส่งซ้ำจากการค้างในแถบ

## เทรนด์ใหญ่และกรอบยืนยัน (HTF)

เปิด **Trade with main trend + confirmation** เป็นค่าเริ่มต้น ควบคุมทั้งสองกรอบพร้อมกัน ทั้งคู่ใช้กฎ EMA/ราคาปิด/ความชันข้างต้นโดยไม่มี ADX และต้องเป็นลำดับ **เทรนด์ใหญ่ > กรอบยืนยัน > กราฟเข้า** อย่างเคร่งครัด

- **Auto** เป็นค่าเริ่มต้นของแต่ละกรอบ: เทรนด์ใหญ่ประมาณ **16 เท่า** และกรอบยืนยันประมาณ **4 เท่า** ของกราฟเข้า ผ่าน `timeframe.from_seconds()` ซึ่งปัดเป็นช่วงที่ Pine รองรับและมีเพดาน 12 เดือน เช่น กราฟ 15 นาที → เทรนด์ใหญ่ `240` / ยืนยัน `60`; กราฟ 1 ชั่วโมง → `960` / `240`; กราฟ 1 วัน → `16D` / `4D` ดูค่าที่เลือกจริงบนป้าย/tooltip
- **Manual**: ตั้งโหมดและเวลาแยกกันสำหรับเทรนด์ใหญ่กับกรอบยืนยัน ค่าในช่องเริ่มต้นเป็น `240` และ `60` ตามลำดับ หากลำดับไม่สูงกว่ากัน, เป็น Tick หรือเลือกช่องว่างซึ่งหมายถึงกราฟเดียวกัน จะบล็อกการเข้าเมื่อเปิดตัวกรอง
- หาก Auto ชนเพดานจนกรอบเท่ากันหรือไม่สูงกว่ากราฟ เช่นกราฟ `12M` ให้เลือกคู่ Manual ที่ยังเรียงได้, ใช้กราฟเข้าที่เล็กลง หรือปิด **Trade with main trend + confirmation**; ปิดแล้วใช้เทรนด์กราฟเข้าเพียงกรอบเดียวกับกฎ pullback เดิม หัวป้าย/สี/จุดเปลี่ยนเทรนด์จึงเปลี่ยนมาอิงกราฟเข้า

อ่านเฉพาะ HTF ที่ปิดแล้วด้วยการเลื่อนค่าหนึ่งแท่งภายในแต่ละ HTF และใช้ `lookahead_on` คู่กัน ค่าใหม่พร้อมใช้เมื่อเริ่มช่วง HTF ถัดไป และบันทึกสถานะ/พิจารณาสัญญาณเมื่อ **แท่งกราฟเข้าปิด** เช่น หากแท่ง 4 ชั่วโมงจบเวลา 12:00 และมีแท่ง 15 นาทีต่อเนื่อง ค่าใหม่จะสะท้อนเมื่อแท่ง 12:00–12:15 ปิด ไม่ได้เปลี่ยนตามแท่ง 4 ชั่วโมงที่ยังวิ่ง EMA, pivot, cooldown และอายุ setup/แผนนับเป็น **จำนวนแท่ง** จึงมีเวลาเดินจริงต่างกันตามกราฟ

## แนวรับ แนวต้าน และพื้นที่ถึงเป้า

ค่าเริ่มต้น pivot ใช้ 3 แท่งซ้ายและ 3 แท่งขวา รับ level เข้ามาหลังแท่งขวาครบและปิดแล้วเท่านั้น ไม่ย้อนสัญญาณไปที่แท่ง pivot เก็บ swing high และ swing low ล่าสุดอย่างละ **20 จุด**

เลือกแนวต้านใกล้ที่สุดที่ **สูงกว่าหรือเท่ากับ** ราคาปิด และแนวรับใกล้ที่สุดที่ **ต่ำกว่าหรือเท่ากับ** ราคาปิด ระดับที่เท่าราคาเข้าจึงไม่ถูกมองข้ามว่าไม่มีสิ่งกีดขวาง เส้นที่เห็นเปลี่ยนได้ตามระดับที่ใกล้ราคาที่สุดในแต่ละแท่งปิด

เปิด **Check room to confirmed swing levels** เป็นค่าเริ่มต้น หากไม่มี level ที่รู้แล้วด้านหน้า จะบล็อกและแสดง `รอแนวรับ–แนวต้านด้านหน้า` เพราะพื้นที่ยังไม่ทราบ หากต้องการยอมรับกรณีนี้ให้เปิด **Allow entries with no known level ahead** เอง ระดับที่เก็บเป็นจุด swing ตามกฎนี้ ไม่ใช่การรับรองว่าได้รวมแนวรับ/ต้านทุกชนิดบนตลาด การซ่อนเส้น S/R ในหมวดการแสดงผลไม่ปิดตัวกรองนี้

## แผน Entry / SL / TP

- **Entry** ใช้ราคาปิดแท่งยืนยัน ปัดตาม tick เป็นราคาอ้างอิง ไม่ใช่ราคาที่โบรกเกอร์ยืนยันว่าจับคู่แล้ว
- **SL** อยู่เลย low ต่ำสุดของช่วงตั้งแต่เตรียม BUY ถึงแท่งยืนยัน หรือเลย high สูงสุดสำหรับ SELL เพิ่ม buffer **0.25 ATR** ค่า ATR เริ่มต้น 14 และใช้ค่าตอนยืนยัน
- **TP** เริ่มจากระยะ SL × **2R** หากเปิดกรอง S/R และรู้ level จะจำกัดเป้าไว้ก่อน level ด้วย buffer **0.1 ATR** ปัด SL ออกห่างและ TP เข้าหา Entry ตาม tick
- หลังจำกัดเป้าและหัก cost buffer ต้องมีระยะ SL/TP อย่างน้อยหนึ่ง tick, reward สุทธิมากกว่าศูนย์ และ reward/risk สุทธิอย่างน้อย **1.5R**

สูตรตรวจสุทธิ: `netRisk = ระยะ Entry–SL + costBuffer`, `netReward = ระยะ Entry–TP − costBuffer`, `netR = netReward / netRisk` ค่า **costBuffer เริ่มต้น 0 จึงยังไม่รวมต้นทุน** กรอก spread, slippage และ commission ไปกลับที่แปลงเป็นหน่วยราคาเอง สคริปต์ไม่มีข้อมูล spread สดของโบรกเกอร์

Entry/SL/TP และค่าประมาณจำนวนถูกตรึงเมื่อออกสัญญาณ มีแผนทำงานได้ครั้งละหนึ่งแผน แท่งเข้าไม่ถูกนำ high/low ก่อนราคาปิดมานับว่าโดน SL/TP ภายหลังเข้า ตรวจการแตะตั้งแต่แท่งถัดไป หากแท่งเดียวแตะทั้งสองจะขึ้น `BOTH TOUCHED / ORDER UNKNOWN` เพราะ OHLC ไม่บอกลำดับ

แผนจบเมื่อแตะ SL, TP หรือครบ **32 แท่งกราฟหลังสัญญาณ** ตามค่าเริ่มต้น ไม่ใช่เวลาเดินจริงตายตัว จะไม่เข้าใหม่ในแท่งเดียวกับที่แผนจบ และต้องรอ setup ใหม่ **เทรนด์เปลี่ยนไม่บังคับจบแผนหรือย้าย SL/TP** หากเทรนด์ใหญ่ไม่ชัดหรือสวนฝั่งแผน จะเพิ่มข้อความ `เทรนด์ใหญ่ไม่หนุนแล้ว` Tooltip และ Data Window เก็บแผนล่าสุดแม้จบแล้ว การแตะระดับเป็นข้อมูลอ้างอิง ไม่ใช่บันทึกผลจับคู่คำสั่งจริง

## คำนวณขนาดสถานะแบบเลือกใช้

`Risk budget` และ `Cash value of 1.0 price move per quantity unit` เริ่มต้นเป็น **0 ทั้งคู่** จึงยังไม่คำนวณจำนวน ต้องกรอกทั้งคู่ให้มากกว่า 0 จึงเปิดใช้ หากช่องใดช่องหนึ่งยังเป็น 0 จะยังไม่มีค่าประมาณจำนวนในรายละเอียดแผน

เลือก `Quantity unit` เป็น units, shares, contracts, lots หรือ coins แล้วกรอกมูลค่าเงินที่หนึ่งหน่วยเปลี่ยนเมื่อราคาขยับ 1.0 จากสเปกสัญญาของโบรกเกอร์ ทั้งงบเสี่ยงและมูลค่าต่อหน่วยต้องเป็น **สกุลเงินเดียวกัน** `Risk currency label` เริ่มต้น USD เป็นเพียงข้อความในรายละเอียด **ไม่มีการแปลงอัตราแลกเปลี่ยน** การเปลี่ยนหน่วยหรือสกุลเงินไม่แปลงค่าตั้งให้อัตโนมัติ

`จำนวนก่อนปัด = riskCash / ((ระยะ SL + costBuffer) × valuePerUnit)` แล้วปัด **ลง** ตาม quantity step หากต่ำกว่า minimum quantity จะบล็อกสัญญาณ (`งบเสี่ยงไม่พอขนาดขั้นต่ำ`) ค่า step/minimum เริ่มต้น **1** หากใช้หุ้นเศษส่วน, ล็อตย่อย หรือเหรียญเศษส่วน ต้องตั้งเองตามข้อกำหนดจริง

ตัวอย่างเฉพาะการคำนวณ: หุ้นราคา USD เลือก shares, งบเสี่ยง 100 USD, มูลค่าต่อการขยับราคา 1.0 เท่ากับ 1 USD ต่อหุ้น, ระยะ SL รวมต้นทุน 2 USD และ step 1 จะได้ 50 หุ้น สูตรนี้ประมาณความเสี่ยงของหน่วยที่มูลค่าเปลี่ยน **เป็นเส้นตรงกับราคา** สัญญา inverse/ไม่เป็นเส้นตรงต้องใช้แบบคำนวณของสัญญานั้น สคริปต์ไม่ได้อ่านยอดเงินหรือสเปกบัญชีโบรกเกอร์

## เวลาข่าวแบบกรอกเอง

กำหนดได้ 3 เหตุการณ์ โดยเปิด `Use event` และใส่วันเวลาให้ช่องนั้น ทุกช่องปิดเป็นค่าเริ่มต้น หน้าต่างบล็อกเริ่มต้น **30 นาทีก่อน** ถึง **15 นาทีหลัง** เหตุการณ์ และรวมแท่งที่ช่วงเปิด–ปิดทับหน้าต่างแม้เพียงขอบเวลา ยกเลิก setup ที่รออยู่และบล็อกการเข้าใหม่ในแท่งดังกล่าว

เมื่อใช้กราฟวัน/สัปดาห์/เดือน การทับช่วงข่าวจะบล็อก **ทั้งแท่งวัน/สัปดาห์/เดือนที่มีเหตุการณ์นั้น** ไม่ใช่เฉพาะไม่กี่นาที สคริปต์ไม่เลือกรายการข่าวให้ตามสินทรัพย์ ผู้ใช้ต้องปรับเหตุการณ์และวันเวลาให้เหมาะกับสัญลักษณ์ที่กำลังดูเอง

วันเวลาใน `input.time` แสดงตาม timezone ของกราฟแล้วแปลงเป็น timestamp ควรตรวจ timezone ก่อนกรอก การเปลี่ยน timezone ภายหลังเปลี่ยนการแสดงเวลา แต่ไม่ย้าย timestamp ของเหตุการณ์

นี่เป็น **รายการข่าวที่ผู้ใช้กรอกเอง ไม่มีการดึงปฏิทินข่าวอัตโนมัติ** Tooltip บอกว่ายังไม่ได้ตั้งเวลา, เวลาข่าวเดิมหมดอายุ หรือกำลังตรวจเฉพาะเวลาที่กรอกเอง สถานะเหล่านี้ไม่ยืนยันว่าตลาดไม่มีข่าวอื่น ต้องอัปเดตวันเวลาและสร้าง Alert ใหม่ตามค่าที่แก้

## ตั้ง Alert

1. ใน **Create Alert → Condition** เลือก **Trend Entries | Main Trend + Confirmation**
2. เลือก **BUY entry confirmed**, **SELL entry confirmed** หรือ **Any entry confirmed**
3. ตั้ง **Once Per Bar Close** แล้วสร้าง Alert ข้อความมี Entry/SL/TP อ้างอิง; แบบรวมใช้ Side `1 = BUY`, `−1 = SELL`

เงื่อนไขแจ้งเปลี่ยนเทรนด์ UP/DOWN/NEUTRAL อิงเทรนด์เดียวกับหัวป้าย: เทรนด์ใหญ่เมื่อเปิดตัวกรอง หรือกราฟเข้าเมื่อปิด เลือกใช้ได้แม้ซ่อนป้าย การซ่อนป้ายไม่ได้ปิด Alert สคริปต์เตรียมเงื่อนไขให้ แต่ต้องสร้าง Alert ใน TradingView เอง และไม่ส่งสัญญาณย้อนหลัง

TradingView เก็บสำเนาสคริปต์และค่าตั้งตอนสร้าง Alert หลังแก้โค้ด, สัญลักษณ์, timeframe, วันข่าว หรือค่าตั้งใด ให้สร้าง Alert ใหม่เพื่อใช้ค่าใหม่

## การทดสอบในโปรเจกต์

ใช้ Node.js และรันจากโฟลเดอร์นี้:

```sh
npm ci --ignore-scripts
npm test
```

ชุดทดสอบใช้ข้อมูล OHLC สังเคราะห์และ PineTS 0.13.1 รัน source จริง ครอบคลุมแนวโน้ม, แท่งปิด, pullback/trigger, การยกเลิก/หมดอายุ, S/R, ต้นทุน, จำนวน, ข่าว และวงจรแผน รวมถึงการรัน source เต็มของกราฟ 15 นาทีพร้อม Auto ยืนยัน 1 ชั่วโมงและเทรนด์ใหญ่ 4 ชั่วโมง ตลอดจนบริบทสัญลักษณ์/กรอบเวลาต่างกัน

ชุดหลายกรอบเวลาตรวจว่าต้องตรงกันทั้งสามกรอบก่อนเข้า, 1 ชั่วโมง/4 ชั่วโมงที่ยังไม่ปิดไม่เปลี่ยนค่าที่ยืนยัน, ค่า 4 ชั่วโมงใหม่ต้องรอกราฟ 15 นาทีปิดก่อนอัปเดตหรือยกเลิก setup, การสวนบนกราฟเข้าไม่เปลี่ยนหัวป้ายเทรนด์ใหญ่ และการกลับทิศของเทรนด์ใหญ่เตือนโดยไม่ย้ายราคาหรือบังคับปิดแผนเดิม

PineTS 0.13.1 จัดการ `timeframe.main_period` ในบริบท request ต่างจากเอกสาร TradingView ทำให้โหมด Manual ที่เลือก HTF ถูกต้อง และ Auto บางกรณีที่ชนเพดาน 12 เดือน รันครบไฟล์ในตัวจำลองไม่ได้ จึงทดสอบ helper/selection/request ของ Manual จาก source จริงแยกตามแต่ละกรอบ ส่วนกราฟ `4M` ที่ Auto ได้ `12M/12M` ทดสอบการเลือกเวลาและข้อความบล็อกจาก source จริงโดยใส่สถานะอื่นเป็นข้อมูลทดสอบ ไม่ได้รัน request ครบไฟล์ ต้องยืนยันกรณีที่ติดข้อจำกัดเหล่านี้บน TradingView ไม่ใช่ข้อผิดพลาดที่พบจากการรันบน TradingView

การใช้ `timeframe.main_period` ทำให้การเลือก HTF ยึดกรอบเวลาหลักแม้อยู่ในบริบท request ผลทดสอบ PineTS เป็นการตรวจพฤติกรรมเสริม **ไม่ใช่การคอมไพล์ด้วย TradingView** และไม่ใช่การทดสอบกำไรหรือหลักฐานว่าค่าเริ่มต้นแม่นยำในทุกสินทรัพย์/กรอบเวลา
